# LTEF design and evidence package

Start with **technical-design.html** for a navigable document, or **technical-design.pdf** for sharing.

- **evidence-matrix.csv**: 28 business requirements mapped to implementation, tests, status and remaining work. Opens in Excel.
- **LTEF-technical-design.drawio**: five editable architecture/data-flow/sequence/model/traceability diagrams. In draw.io, choose File → Open From → Device.
- **diagrams.pdf**: a large-format, five-page diagram set for review and sharing.
- **01…05 SVG files**: standalone diagram previews.
- **technical-design.md**: editable document source.
- **verification-record.md**: actual test commands, results and scope.
- **mcp-verification.json**: official draw.io MCP initialization/tool-discovery record. Restart Codex to load the newly configured connector.
- **evidence/**: synthetic test-session screenshots and reproducible build/check scripts.
- **SHA256SUMS.txt**: package file fingerprints. These identify contents; they are not a digital signature.

In the app, sign in and choose Data requirements: **Choose metrics → Prepare data → Check & run**. Researcher/Administrator access is required for file checks and evaluation runs.

The implementation remains a local research prototype. Input availability checks do not establish scientific validity, and starter data is synthetic. Production and domain-validation gaps are explicit in the matrix.
